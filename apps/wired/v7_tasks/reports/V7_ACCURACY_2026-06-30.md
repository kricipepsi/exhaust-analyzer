## 2. Method (how each dimension is scored)

Six independent dimensions per accuracy case (driver: `score_case()` in
`apps/wired/v7/run_suite.py`). A dimension is `NA` when the oracle leaves its column
blank; an overall case `PASS` requires **no dimension to be FAIL**.

| Dim | Engine field read | Oracle column | Pass rule |
|---|---|---|---|
| `fault_family` | `diagnostic_verdict.fault_family` | `expected_fault_family` | case-insensitive equality |
| `fault_code` | `diagnostic_verdict.fault_code` | `expected_fault_code` | case-insensitive equality (blank/`null` → NA) |
| `state` | derived from `is_fault_detected` | `expected_state` | mapped state equality |
| `confidence` | `diagnostic_verdict.confidence_score` | `[min,max]` | `min ≤ score ≤ max` |
| `perception_gap` | `performance_analytics.o2_sensor_bias_verdict` present? | `expected_perception_gap` | bool equality |
| `demotion_note_contains` | text fields (headline/remediation/reasons) | `expected_demotion_note_contains` | substring present |

Invalid cases (`tag == invalid`, 20 rows) are scored only on `expected_crash_abort`
against the engine's `execution_meta.degradation_mode` (`FATAL_INCOMPLETE`) or a raised
validation exception.

**Accuracy `%` denominator is the 294 `accuracy`-tagged cases only** — invalid/excluded
rows never enter the accuracy ratio. Stated per the task's success criteria.

### 4.1 `fault_code` — 294/294 — ID-namespace mismatch *(hypothesis: oracle-correction, possibly engine-bug)*

Root cause is conclusive from the data:

- **Engine emits** `diagnostic_verdict.fault_code` in **short form**: `MF-001`, `LC-001`,
  `RM-001`, `CF-001`, `SF-002`, `NF-001`, … (this is `fault_id` = the router's winning
  candidate id; `fault_atlas_router.py:2201` sets `fault_code=fault_id`).
- **Oracle expects** the **canonical KG fault_id** in **`ERR-` form**: `ERR-LC-001`,
  `ERR-RM-003`, `ERR-MF-002`, `OPTIMAL_HEALTH`, … (T-V7-3 pinned these from
  `FaultAtlasKG`; the live KG node files `labs/comlab/comlab/config/kg/*.json` use
  `ERR-MF-001`-form ids, confirmed by inspection).
- Result: **0 exact matches out of 294** — the two id spaces never coincide, even when
  the *family* is correctly routed.

This is a contract-surface question, not 294 independent defects:

- If the **canonical** code is the `ERR-`-prefixed KG id (the KG, the global registry,
  and 6859 in-tree references all use `ERR-`), then the **engine verdict is under-
  qualified** — it surfaces the bare candidate id instead of the resolved canonical
  `fault_id`. → *engine-bug* (verdict should carry the resolved KG id), **or**
- If the bare `MF-001` form is the intended public verdict code, then the **oracle column
  is over-qualified** and T-V7-3 should be corrected to the short form. → *oracle-
  correction*.

**Recommended disposition:** the KG/registry canon is `ERR-`-prefixed, so the leading
hypothesis is *engine-bug* (resolve `fault_id` through the KG before emitting it on the
verdict) with *oracle-correction* as the cheaper alternative. **Owner/architect decides
which surface is canonical.** Logged as `F-V7-CODE-NS` below.

### 4.2 `confidence` — 273/294 — saturation above the calibrated band *(hypothesis: oracle-correction or engine-bug)*

Predicted `confidence_score` distribution across the 294 accuracy cases:

| predicted score | cases |
|---:|---:|
| 1.00 | 172 |
| 0.95 | 79 |
| 0.93 | 18 |
| 0.90 | 22 |
| 0.80 | 2 |
| 0.96 | 1 |

172/294 cases report **exactly 1.0**; 251/294 report ≥0.95. The oracle windows are
calibrated mid-band (e.g. `[0.7, 0.9]`, `[0.65, 0.85]`), so only **21/294** land in
band. Either the engine over-states certainty (winner score is passed through raw as
`confidence_score`, `fault_atlas_router.py:2205`) or the oracle bands are mis-calibrated
against the current scorer. Single root either way. Logged as `F-V7-CONF-SAT`.

### 4.3 `perception_gap` — 100/294 — O2-bias verdict presence mismatch

Scored on whether `performance_analytics.o2_sensor_bias_verdict` is present vs the
oracle's `expected_perception_gap` bool. 100 mismatches — a real signal worth a second
pass once §4.1/§4.2 are resolved (it may co-move with specific families). Logged as
`F-V7-PGAP`.

### 4.4 `state` (19) and `demotion_note_contains` (5) — minor

Low-volume, likely case-specific. Roll up under `F-V7-STATE` and `F-V7-DEMOTE`; inspect
after the systematic defects clear (they may shrink further once routing is corrected).

### 4.5 Invalid/negative cases — 17/20 PASS

The 20 `invalid`-tag rows test bad-input handling. **17 correctly reach
`FATAL_INCOMPLETE`** as the oracle expects. **3 FAIL:** `CASE-043`, `RULE-NOx-1`,
`YAML-PDF_HI_007` — all expected `fatal_incomplete` but the engine did **not** abort
(no exception, no `FATAL_INCOMPLETE`); it produced a normal verdict instead. These are
genuine **missing-fatal-gate** candidates (the engine accepted input the oracle considers
incomplete). Logged as `F-V7-FATALGATE`. **0 engine crashes** across all 314 cases —
bad input degrades, it does not throw.

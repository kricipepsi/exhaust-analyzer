## 4. `v1_crash` list — 93 cases, all one defect

`USE_V2_REGISTRY=0` produced **93 engine crashes** (vs v2's clean 0). The run was not
aborted — the driver catches the exception per case and counts it. Every crash is the
**same** exception:

```
AttributeError: 'NoneType' object has no attribute 'confirmed_dtcs'
```

i.e. the v1 native path dereferences `dtc_lab_output.confirmed_dtcs` unconditionally,
but the v7 corpus contains cases whose DTC payload is `None` (no DTCs reported). The v2
registry shim guards that path; the v1 native path does not. This is a **genuine v1-path
defect surfaced by the suite**, not a suite bug, and per task scope it is **recorded, not
patched here** (OUT: any engine fix). It depresses v1's number — 93 of its 269 family
FAILs are crashes, not misroutes — but even on the 201 non-crashing cases v1 routes
25/201 ≈ 12 % family, still far below v2's 48 % on the full set, so the conclusion
(v2 > v1) does not depend on the crashes.

## 6. Bottom line

**On a common ruler (same corpus · same oracle · same 6-dim scorer), the v2 registry
routes better in 8 families, worse in 0, net +116 cases (+39.5 pts: 8.50 % → 47.96 %
family routing) vs the v1 legacy path — and stops 93 crashes the v1 path produces on
DTC-less cases.** The owner's "v1 ≈ 51 %, v2 ≈ 48 % — similar despite a month of effort"
premise is, on a same-ruler measurement, **falsified in the opposite direction**: the
rebuild did not stand still, it roughly 5.6×-ed family-routing accuracy on the v7 suite.

Two honest caveats:
1. This is the **v1 proxy** (the engine's `USE_V2_REGISTRY=0` legacy path), not true-v1.
   Step 0 shows it is a **high-fidelity** proxy (98 % rule-set identical to 4dV1), so the
   comparison is sound for routing. A true-v1 harness over `/home/m/Desktop/4dV1` remains
   held in reserve if the owner wants the number re-verified on real v1 emitters.
2. The 93 v1 crashes are a real v1-path defect (unguarded `confirmed_dtcs` deref), not
   tuned here. They bias v1 *downward*; even setting them aside, v1 routes 25/201 ≈ 12 %
   on non-crashing cases vs v2's 48 % on all 294 — the conclusion is robust.

**Disposition input (not fixed here):** tuning/revert effort should target the **4
unchanged families** (`ecu_fault`, `exhaust_leak`, `mechanical_wear`, `non_starter`) —
these are where v2 *also* still fails (the dead-routing `F-V7-DEAD-ROUTE` and the
`ecu_fault` dispersion `F-V7-ECU-ROUTE` already open in the ledger). There is no
family where a "revert to v1" call would improve routing. Logged as `F-V7-V1V2`.

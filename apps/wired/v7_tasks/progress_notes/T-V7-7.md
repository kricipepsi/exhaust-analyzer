## Findings (one-line)

- The **v2 default path** emits the short `rule_id` (`MF-001`); the v1 path emits
  `ERR-` ids from `global_fault_registry.json`. The v2 path **never consults the
  KG** (passthrough-default enrichment) — there is **no short→`ERR-` resolution**
  anywhere.
- The 73 v2 `rule_id`s are **globally unique** (0 collisions) — short ids are
  unambiguous across families.
- **No live consumer** of `diagnostic_verdict.fault_code` depends on the `ERR-`
  prefix for named-fault verdicts. The only `ERR-`-form readers are v1-path-only
  engine internals and the **fatal-gate abort codes** (`ERR-ABORT-00x`), which
  are a separate id space emitted on BOTH paths.
- **Recommendation: Option B** — re-pin the v7 oracle `expected_fault_code` to
  the short `rule_id` for **named-fault rows only**, preserving `ERR-ABORT-*`
  abort rows and `OPTIMAL_HEALTH`. Zero engine change; zero consumer impact.
- **Separate defect surfaced (for architect triage, not in scope):** the v2 path
  orphans the KG `fault_enrichment` (passthrough defaults) — suggest
  `F-V7-ENRICH-ORPHAN`, not folded into this fix.

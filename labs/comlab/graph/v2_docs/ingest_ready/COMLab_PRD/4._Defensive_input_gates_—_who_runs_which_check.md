## 4. Defensive input gates — who runs which check

The COMLabDesign proposal centralised plausibility checks in COMLab.
The horizontal-DNA flip moves most of them to the producer labs, where
the DNA context is local. COMLab keeps only the gates that intrinsically
require all four labs' data to evaluate.

### 4.1 Producer-lab gates (run on submit of screens 2, 3, 4 — not COMLab)

### Gate: DNA-relative RPM ceiling
- **Producer**: OBDLab
- **Trigger**: `engine_rpm > rated_rpm` from DNA
- **What the user sees**: Inline error on Screen 3: "Entered RPM exceeds this engine's redline (rated 5200). Re-check value."

### Gate: Decimal-misplacement sentinel
- **Producer**: OBDLab / GASLab
- **Trigger**: Value > 10× plausible bound
- **What the user sees**: Inline error on the relevant screen: "Value 140 is unusually high for CO%. Did you mean 1.40?"

### Gate: Thermal gate (ECT < 70 °C for trim analytics; ECT < 75 °C for engine-state bucket)
- **Producer**: OBDLab
- **Trigger**: `coolant_temp_c < 70` and analytics needed
- **What the user sees**: Inline warning on Screen 3: "Engine is cold (ECT 62 °C). Warm to ≥70 °C before reading fuel trims." Wizard offers "skip trim analytics" or "go back". Two thresholds coexist: 70 °C gates trim analytics (`ENGINE_COLD`), 75 °C gates the `COLD_OPEN_LOOP_INVALID` engine-state bucket. Both must be satisfied before closed-loop diagnostics run.

### Gate: Gas sample validity
- **Producer**: GASLab
- **Trigger**: `gas_co + gas_co2 + gas_o2` outside 14–18%
- **What the user sees**: Inline error on Screen 2: "Gas sample fails validity check — likely air leak at probe. Re-seat and re-sample."

### Gate: Single-bank Bank 2 enforcement
- **Producer**: OBDLab
- **Trigger**: Bank 2 trim values entered when `number_of_banks == 1` from DNA
- **What the user sees**: Fields hidden by DNA gating; if somehow submitted, OBDLab strips them and warns.

### Gate: DTC format
- **Producer**: DTCLab
- **Trigger**: DTC string fails `^[BCPU][0-3][0-9]{3}$`
- **What the user sees**: Inline error on Screen 4 next to the offending row.

### 4.2 COMLab gates (run in Stage A of the pipeline, on the assembled payload)

### Gate: Schema/contract drift
- **Trigger**: Pydantic ValidationError
- **Error code**: `ERR-CONTRACT-001` (regex/range) or `ERR-CONTRACT-002` (cross-field)
- **What the user sees on Screen 6**: "Internal payload mismatch. Please re-submit. If the error persists, your wizard version may need updating."

### Gate: Schema version mismatch
- **Trigger**: `vehicle_dna.schema_version` older than `MIN_SUPPORTED_SCHEMA_VERSION`
- **Error code**: `ERR-ABORT-005`
- **What the user sees on Screen 6**: "Your client app needs updating to communicate with the diagnostic engine."

### Gate: Sample validity (final guard)
- **Trigger**: `gas_lab_output.sample_validity != "VALID"` (and GASLab not suppressed)
- **Error code**: `ERR-ABORT-001`
- **What the user sees on Screen 6**: Same wording as the GASLab inline guard — surfaces the same root cause if it somehow slipped through.

### Gate: Engine warmed (final guard)
- **Trigger**: `obd_live_data.engine_warmed == false` (and OBDLab not suppressed)
- **Error code**: `ERR-ABORT-002`
- **What the user sees on Screen 6**: Same wording as the OBDLab inline guard.

### Gate: VIN unresolvable
- **Trigger**: `vehicle_dna.vin_dna.confidence == "NONE"`
- **Error code**: `ERR-ABORT-004`
- **What the user sees on Screen 6**: "Vehicle could not be identified from the VIN. Diagnosis cannot run without vehicle identification."

COMLab's gates are intentionally a thin safety net behind the producer
gates. The user should almost never see a COMLab-level abort if the
wizard is working correctly — if they do, the message names the
specific upstream cause.

### 4.3 Null vs zero — the integrity rule

The product treats an unfilled field (`null`) and an explicit zero
(`0.0`) as different facts, especially for fuel trims. The wizard never
auto-fills numeric fields with `0`. When the technician leaves a field
blank, the payload carries `null`; when the technician types `0`, the
payload carries `0.0`. COMLab's degradation classifier (Stage A step 5
of HLD §4.1) reads `null`s as missing-evidence; readers of `0.0` treat
it as a real measurement. The user does not need to know this rule
exists — the wizard simply does the right thing by not pre-populating
numeric fields with zeros.

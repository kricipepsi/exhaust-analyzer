## 9. Out of scope for v1 (candidates for v2+)

These items were considered and explicitly deferred. Each names the
conditions under which it would graduate into a future release.

### Item: Diesel powertrains
- **Defer reason**: Lambda chemistry differs; AFR target differs; would require parallel rule set
- **Graduation condition**: Sufficient v1 telemetry to design a clean diesel pipeline (estimated v2.0)

### Item: Cold-start fault analysis
- **Defer reason**: Closed-loop assumptions break below ECT 70 °C; requires open-loop rule track
- **Graduation condition**: When OBDLab models cranking/cold-running PIDs

### Item: Real-time / streaming live data
- **Defer reason**: Wizard-based manual input is the v1 contract
- **Graduation condition**: Live-Bluetooth path designed for a separate "Live mode" alongside wizard, not replacing it

### Item: Part-cost / labour-hour estimation
- **Defer reason**: No consumer in the engine; would require external supplier data feed
- **Graduation condition**: Product strategy decision; not a technical blocker

### Item: Free-text symptom AI parser
- **Defer reason**: SymptomLab v1 is tier_1 + tier_2 only; free-text logged but not analysed
- **Graduation condition**: LLM-side pricing/latency justifies adding it

### Item: Multi-fault verdicts (e.g. "fault A AND fault B simultaneously")
- **Defer reason**: Confidence-ranking model is single-winner
- **Graduation condition**: Product evidence that real-world cases are multi-fault often enough to matter

### Item: Persistent user accounts / session history
- **Defer reason**: v1 is stateless beyond audit
- **Graduation condition**: Product decision (privacy/account model)

### Item: OEM-specific deep DTCs (U-codes, manufacturer-specific)
- **Defer reason**: DTC_REGEX accepts them but routing tags don't cover them
- **Graduation condition**: DTCLab adds OEM routing dictionaries

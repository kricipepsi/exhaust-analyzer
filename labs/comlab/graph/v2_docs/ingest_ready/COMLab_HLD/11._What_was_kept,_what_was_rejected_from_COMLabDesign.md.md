## 11. What was kept, what was rejected from `COMLabDesign.md`

For traceability — the COMLabDesign proposal was a substantial
document. This HLD adopts only the parts that survive reconciliation
with the rest of 4DLab.

### From the proposal: Passive Static Knowledge Graph, decoupled from rule engine
- **Disposition**: **Kept** as the Fault-Atlas KG (§5).
- **Why**: Genuine architectural addition; cleanly separates "rule fired" from "what to fix".

### From the proposal: `global_fault_registry.json` as flat rule registry
- **Disposition**: **Kept** (already in v0.1).
- **Why**: Matches existing OrchestratorLabBP and the §4.2 walk.

### From the proposal: `orchestrator_skg_map.json` JSON shape
- **Disposition**: **Kept in spirit** as `fault_atlas_kg.json`.
- **Why**: Renamed to "KG" honestly; same on-disk pattern.

### From the proposal: `fault_enrichment` block in the outbound payload
- **Disposition**: **Kept** (§7.4).
- **Why**: Each field has a named UI consumer.

### From the proposal: `user_input_echo_audit` block
- **Disposition**: **Rejected from COMLab's contract.**
- **Why**: No consumer in COMLab analytics or routing. UI layer's responsibility. Open question §12 Q4.

### From the proposal: Plausibility / decimal-misplacement sentinels in `lab_pipeline_aggregator`
- **Disposition**: **Moved upstream.**
- **Why**: Belongs at per-lab DNA-aware ingestion (post-horizontal-DNA flip). COMLab sees pre-validated data.

### From the proposal: `idle_baseline` / `raised_2500_rpm` two-RPM matrix as the inbound shape
- **Disposition**: **Rejected.**
- **Why**: Contradicts `SEMANTIC_CONTRACT.md`. The two-RPM bucketing is internal to GASLab/OBDLab; COMLab sees one already-bucketed payload per lab.

### From the proposal: VIN parsing inside `horizon_context_injector.py`
- **Disposition**: **Rejected.**
- **Why**: DNALab pre-computes `resolved_horizon` and ships it. `DNALab_TO_COMLab_FLOW.md` §8 explicitly forbids COMLab-side VIN string-slicing.

### From the proposal: 4-script module count (drops `symptom_router.py`)
- **Disposition**: **Rejected.**
- **Why**: `symptom_router` produces the `LabRoutingDirective` consumed by Stage A and Stage B. Required.

### From the proposal: Stub-grade `OBDLiveDataPayload` (only shrtft1/longft1/engine_warmed)
- **Disposition**: **Rejected.**
- **Why**: `data_flow_report.md` §2 already flagged the gap; the full computed-analytics surface (`ve_pct`, `total_trim_correction_delta`, `normalized_obd_lambda`, etc.) is required for the router to function.

### From the proposal: Absence of `SymptomDNA` in the inbound payload
- **Disposition**: **Rejected.**
- **Why**: T-FX-5 elevates `symptom_dna` to top-level; the four routing-directive flags depend on it.

### From the proposal: Hard-coded `0.0` injection for missing trims on legacy cars
- **Disposition**: **Rejected for non-legacy paths.**
- **Why**: `null`-vs-`0.0` distinction is correct in the proposal but per-lab DNA-aware ingestion is the right enforcement point. COMLab keeps the `GAS_DOMINANT` degradation mode for the legacy-no-scanner case but does not silently substitute zeros into trim fields.

### From the proposal: `WORN_VALVE_SEALS` as the fault key
- **Disposition**: **Renamed.**
- **Why**: Use `fault_id` (e.g. `ERR-E2-MECH-082`) per the existing registry convention, not free-form `SCREAMING_SNAKE` strings. The KG's `fault_name` field carries the snake_case human-readable form (`worn_valve_stem_seals`).

### From the proposal: 2.5 MB total config size envelope
- **Disposition**: **Deferred to DLD.**
- **Why**: Resource budget belongs in DLD; flagged here so the LLD is built with it in mind.

### From the proposal: 250 ms latency target
- **Disposition**: **Deferred to DLD.**
- **Why**: Same.

### From the proposal: Two parallel "HLD: Run-time State" + "HLD: Manual User Input Matrix" sections in the proposal
- **Disposition**: **Collapsed into one HLD here.**
- **Why**: The manual-input dimension belongs in the PRD; this HLD covers architecture.

## 3. Latency budget — per-stage allocation

The 250 ms p95 end-to-end budget is allocated across the HLD stages as
follows. Each stage owns its slice; an LLD-level optimisation that
trades stage budgets is allowed if and only if the sum stays ≤ 250 ms.

### Stage: JSON parse + Pydantic gate (Stage A.1)
- **HLD ref**: §4.1 step 1
- **Budget**: 40 ms
- **Notes**: Dominant cost is Pydantic v2 model construction

### Stage: Schema version + fatal gates (A.2 + A.3)
- **HLD ref**: §4.1 steps 2–4
- **Budget**: 5 ms
- **Notes**: Cheap arithmetic and lookups

### Stage: Routing directive + degradation classify (A.4 + A.5)
- **HLD ref**: §4.1 steps 4–5
- **Budget**: 5 ms
- **Notes**: `route_symptom()` is a constant-time table lookup

### Stage: DNA projection (A.6)
- **HLD ref**: §4.1 step 6 + §6
- **Budget**: 10 ms
- **Notes**: Three frozen-Pydantic model builds

### Stage: Sanitized assembly (A.7)
- **HLD ref**: §4.1 step 7
- **Budget**: 5 ms
- **Notes**: Pure dict merge

### Stage: Fault-atlas walk (Stage B)
- **HLD ref**: §4.2
- **Budget**: 60 ms
- **Notes**: Up to 120 rule rows × ≤ 5 operator clauses each

### Stage: KG resolve (Stage C)
- **HLD ref**: §4.3
- **Budget**: 5 ms
- **Notes**: O(1) dict lookup for winner + ≤ 5 sibling lookups

### Stage: Power-loss analytics (Stage D)
- **HLD ref**: §4.4
- **Budget**: 15 ms
- **Notes**: Pure math; no I/O

### Stage: Serializer (Stage E)
- **HLD ref**: §4.5
- **Budget**: 25 ms
- **Notes**: Pydantic model dump + orjson serialise

### Stage: **Slack**
- **HLD ref**: 
- **Budget**: **80 ms**
- **Notes**: Cushion for GC pauses, jitter, future stages

### Stage: **Total**
- **HLD ref**: 
- **Budget**: **250 ms**
- **Notes**: 

The 80 ms slack is deliberate; without it a single GC pause at p99
would blow the budget. The slack is **not** budget for new
functionality — adding work requires reallocating from the slack with
a DLD revision.

Latency is measured by `perf_counter()` deltas around each stage
boundary, emitted as the `stage_latency_ms.*` fields in the
structured log line (§5.3). The build-validation script (§7) runs a
synthetic benchmark on the e2e fixture corpus and fails the build if
p95 of any stage exceeds 110 % of its budget.

## 11. Failure modes and recovery

### 11.1 Failure-to-recovery matrix

### Failure: Config file missing at boot
- **Detection**: Phase 2 of boot (§4)
- **Recovery**: Process exits non-zero (78) before serving
- **Operator action**: Restore file from VCS; restart

### Failure: KG/registry drift at boot
- **Detection**: Phase 3 of boot (§4)
- **Recovery**: Process exits non-zero (78)
- **Operator action**: Fix the offending PR (CI should have caught it — investigate why §7 step 3 passed)

### Failure: Pydantic validation error mid-session
- **Detection**: Stage A.1
- **Recovery**: Per-session abort `ERR-CONTRACT-001`; pipeline.aborted log; next session unaffected
- **Operator action**: None — producer-lab regression. Page producer-lab owner if rate spikes.

### Failure: Producer payload field missing that v1 contract requires
- **Detection**: Stage A.1
- **Recovery**: Per-session abort with field path
- **Operator action**: Same as above.

### Failure: Registry walk evaluates 0 truthy rules
- **Detection**: Stage B step 5
- **Recovery**: `OPTIMAL_HEALTH` verdict returned; `stage_b_walk.no_winner` WARN
- **Operator action**: None — legitimate outcome. Investigate if rate spikes above the historical baseline.

### Failure: KG lookup miss at runtime (`ERR-stage_c_kg.err_lookup_miss`)
- **Detection**: Stage C
- **Recovery**: Should never happen; protected by §7 step 3. If it does → per-session abort, page COMLab owner
- **Operator action**: Inspect the offending fault_id; verify CI caught the drift

### Failure: Analytics divide-by-zero / NaN
- **Detection**: Stage D
- **Recovery**: Internal stage error caught; pipeline.aborted with internal error
- **Operator action**: Page COMLab owner; reproduce with the session_id from the log

### Failure: Response serialise failure
- **Detection**: Stage E
- **Recovery**: Same as analytics — caught, internal error
- **Operator action**: Page COMLab owner

### Failure: Process OOM
- **Detection**: host signal
- **Recovery**: Process killed; restarted by supervisor
- **Operator action**: Investigate RSS growth — may indicate a regression in §2.1 ceiling

### Failure: Boot time exceeds 1.5 s
- **Detection**: startup observability
- **Recovery**: Process serves, but ops dashboard shows yellow
- **Operator action**: Investigate config-file growth or new schema validator slowness

### 11.2 Graceful degradation paths (not failures)

These are by-design and never page anyone:

- `suppress_gaslab` (engine_state == won_not_start) → `degradation_mode == GAS_DOMINANT`,
  pipeline proceeds, PRD §6.3 yellow banner shown.
- `SymptomDNA.engine_state == won_not_start` → producer labs suppressed
  via routing directive, pipeline proceeds with DTC-only evidence.
- `obd_live_data.engine_warmed == false` AND OBDLab suppressed → no
  abort.

### 11.3 No automatic retry inside COMLab

COMLab does not retry a failed session. The user resubmits, and the
new session is a new session (new `session_id`). Retry policy is the
caller's choice. (For schema/contract errors this is correct — retrying
the same payload changes nothing.)

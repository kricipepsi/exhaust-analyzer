## 4. Checksum Architecture (validate_vin_checksum)

NHTSA modulo-11 (49 CFR Part 565) with three documented bypass paths, in order:

### Bypass: Non-NHTSA WMI
- **Trigger**: `country ∈` European set ∪ {Japan, South Korea, India}
- **Rationale**: ISO 3780 — check digit never mandatory outside US/CA/MX market

### Bypass: OPSI corrupt prefix
- **Trigger**: `vin[:3] ∈ {3MZ, 3MD, 3MV}`
- **Rationale**: T-FX-5 finding: 1,866 Mexican Mazda VINs with corrupt pos-9 in Slovenian DMV data

### Bypass: Non-standard pos-9
- **Trigger**: `vin[8] ∉ "123456789X"`
- **Rationale**: European 1990s vehicles used `Z`/`0` as a dummy check character

When none of the bypasses apply, the standard transliteration + position-weights
computation runs: `remainder = Σ(value × weight) % 11`, expected `= "X"` if remainder
is 10 else `str(remainder)`, compared to `vin[8]`.

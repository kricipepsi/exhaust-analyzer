## Method

**Population.** `grep -rn "# wiki: §" --include=*.py labs apps` returns 316 lines. All 316 come from `labs/obdlab`, `labs/dtclab` and `labs/comlab/comlab/schemas/vocabulary.py`; none come from `apps/`. **Tests are included.** AGENTS.md states the literal rule with no test exemption, so all 316 lines are checked. Totals are reported separately for production (278) and tests (38). The uncited-literal pass covers production code only (`labs/*/<pkg>/`, excluding `tests/`), as the brief asks.

**Citation grammar** (inferred from the 316 lines):
```
"# wiki:" SP CITE { SP "/" SP CITE } [ SP ("—"|"-") NOTE ]
CITE := "§" SECNUM [ SP WORD ]        e.g. §6.4 · §6.4 UNKNOWN · §5 / §12.1
```
- A bare `§` does not name a file. The governing document is found by walking outward from the line: innermost class or def docstring, then the module docstring, then each package `__init__` docstring. The first `*.md` named at that level that has the section wins. If a level names the lab's own `wiki/` file together with another document, the lab wiki wins. If no docstring names a document, the lab's own `labs/<lab>/wiki/*.md` is used.
- In practice this gives three rules:
  - obdlab resolves to `labs/obdlab/wiki/OBDLab_KG_Wiki.md`.
  - dtclab resolves to `labs/dtclab/docs/DTC_VOCABULARY.md`, through `dtclab/__init__.py` "(wiki: DTC_VOCABULARY.md)". Exception: `Mode06MonitorState.MONITOR_ABORTED` resolves to `wiki/10_nonstart_diagnostics.md` through its class docstring.
  - comlab resolves to `labs/comlab/wiki/`.
- A section is a markdown heading whose first token is `SECNUM`. Its text runs to the next heading of the same or higher level, so sub-sections are included. Section numbers inside the NOTE (for example "… §11.1") are treated as secondary references and are not checked.
- The code line is the citation's own line. For a comment-only citation it is the next line if that line is code (the "comment above" style). Otherwise it is the previous line if that is code (the "comment below" style used in `payload.py`, `freeze_frame.py` and `mode06_result.py`).

**Value check.** Python `tokenize` collects the NUMBER tokens on the code line (a unary minus is folded in) and its STRING tokens (docstrings excluded). A number matches if its absolute value appears in the section text, with any spacing or unit around it (`0.45` = `0.45 %` = `~0.45 V`). A ×100 or ÷100 percent/fraction equivalence also matches. If the section has a markdown table row naming the field on the code line, the number must appear **in that row**. This row check caught `intake_air_temp_c le=140`, which a whole-section search had matched against the `coolant_temp_c` row's 140. Strings are matched case-insensitively as substrings.

**Classes.** `RESOLVED+MATCH`, `RESOLVED+VALUE_ABSENT`, `RESOLVED+NO_LITERAL` (the citation is resolved but its line carries no literal), `AMBIGUOUS` (more than one candidate document has the section at the deciding level), `UNRESOLVED_SECTION` and `UNRESOLVED_FILE`.

**Uncited-literal rule.**
- Scanned: every int or float literal in `labs/*/<pkg>/**/*.py` (comlab, dnalab, dtclab, gaslab, obdlab, symptomlab, vinlab), excluding tests.
- Kept only if threshold-shaped:
  - an operand of an ordering comparison (`<`, `<=`, `>`, `>=`, or float `==`);
  - a `ge`/`le`/`gt`/`lt`/`min_length`/`max_length`/`default` keyword value;
  - a `min()`/`max()` clamp argument;
  - the value of an UPPER_CASE constant;
  - a dict value.
- Excluded:
  - 0, 1 and -1;
  - comparisons involving `len(...)`;
  - integer `==`/`!=`/`in` comparisons (categorical, e.g. `banks == 2`, `cyl in (3, 4, 6, 8)`);
  - indexes, slices, arithmetic factors and call arguments.
- A literal counts as **cited** if any of these carries `wiki` or a `§` reference: its line, the contiguous comment block above it, the comment line directly below it, or any line of the enclosing statement (for `if`/`while`, the condition).

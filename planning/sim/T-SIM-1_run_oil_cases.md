# T-SIM-1 — Run the 5FR oil-burn simulation (all 5 cases) & capture results

**Authored:** 2026-06-21 (architect, Cowork). **Type:** run + capture (no lab code changes).
**For:** picking the single most demanding case for the presentation.
**Scope:** the **standalone** simulation only (`planning/sim/oil_burn_5fr_sim.py`) — it mocks the
post-cat-trim pipeline that PCT-1…PCT-10 will build for real. Do **not** wire it into the labs.

### Goal ###

Execute the simulation for **all five** oil-consumption cases on the 5FR, confirm every case routes
to its expected `MW-00x`, and emit a structured results artifact + a demand ranking so the
architect/owner can choose one case to feature. Proven done when the run prints **5/5 ALL GREEN** and
produces `oil_burn_5fr_results.json` plus a short results table.

### What to do (run every step, in order) ###

0. **Start Jaeger** (native binary, no Docker) if not already up, and confirm the UI loads:
   ```powershell
   Start-Process "C:\Users\Petra\Downloads\jaeger-2.19.0-windows-amd64\jaeger.exe"
   Start-Sleep -Seconds 3
   (Invoke-WebRequest http://localhost:16686/ -UseBasicParsing -TimeoutSec 5).StatusCode  # expect 200
   ```
1. **Ensure OTel deps** in the wired venv:
   ```powershell
   C:\Workspace\.venv-wired\Scripts\python.exe -m pip install opentelemetry-sdk opentelemetry-exporter-otlp-proto-grpc
   ```
2. **Data pass** (writes `planning/sim/oil_burn_5fr_results.json`):
   ```powershell
   cd C:\Workspace
   C:\Workspace\.venv-wired\Scripts\python.exe planning\sim\oil_burn_5fr_sim.py --json
   ```
3. **Traced pass** into Jaeger (sets OTLP env, runs, opens UI):
   ```powershell
   .\planning\sim\run_sim_traced.ps1
   ```
   Confirm **5 traces** under service `wiredv2-oil-case` at http://localhost:16686, each a
   `oil_case_<id> → gas_state → post_cat_trim → verdict` span tree. (See `JAEGER_DEMO_README.md`.)
4. **Capture** console output + JSON into `planning/sim/RUN_RESULTS_<date>.md`: the 5-row routing
   table (case · gas state · B1S2 signature · verdict · pass), the **demand ranking**, and a line
   confirming the 5 traces are visible in Jaeger.
5. **Parity check** against `planning/OIL_CASE_SIGNATURES_5FR.md` and
   `planning/sim/OIL_BURN_5FR_SIM_RESULTS.md` — verdicts and B1S2 signatures must match. If any row
   disagrees, **stop and report** (do not edit numbers to force a match).
6. **Hand back** the routing table + demand ranking + Jaeger-trace confirmation so the owner picks
   the presentation case (expected top: PCV MW-008 and Turbo MW-009, demand 4.0).

If any step errors, stop at that step and report the exact message — do not skip ahead.

### Success criteria ###

- `python3 planning/sim/oil_burn_5fr_sim.py` exits 0 and prints **`RESULT: 5/5 … ALL GREEN`**.
- `oil_burn_5fr_results.json` exists with one entry per case carrying `verdict`, `confidence`,
  `demand_score`, and `demand_reasons`.
- `RUN_RESULTS_<date>.md` records the routing table + demand ranking.
- Reported back: the **top-ranked (most demanding) case(s)** by `demand_score` for the owner to pick.
  (Current expectation: PCV `MW-008` and Turbo `MW-009` tie highest; confirm.)

### Files to touch ###

- `planning/sim/RUN_RESULTS_<date>.md` (CREATE — captured output)
- `planning/sim/oil_burn_5fr_results.json` (GENERATED by `--json`)
- No other files. The simulation script is the input, not a target to modify.

### Out of scope ###

Any change to the real labs / registry / decoder (that is PCT-1…PCT-10 + T-VIN-FIX-3). Changing the
case numbers (they are locked to `OIL_CASE_SIGNATURES_5FR.md`). No graphify.

### Hand-back ###

Post the routing table + demand ranking. The architect/owner then selects **one** case for the
presentation; the most demanding is the strongest showcase because it cannot be diagnosed by gas
chemistry alone — it requires the post-cat fuel-trim discrimination (e.g. PCV's divergent split or the
turbo's DFCO-decoupled trim).

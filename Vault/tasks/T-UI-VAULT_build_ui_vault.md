## Scope (1 paragraph)

With the doc-only corpus mode live (`T-UI-VAULT-SUPPORT-1`), author the **architect-named consumer
map** for the UI design corpus and build its vault tier. The corpus is two notes —
`apps/ui/4DLab_UI_FieldMap.md` (the field/consumer contract) and `apps/ui/StreamliteUI.md` (rendering
patterns). Frame the FieldMap with its real, existing consumer; decide whether StreamliteUI frames or
stays `plain:`. Dry-run clean → build → confirm the tier, landing note, `.base` views, System-Map and
PROVENANCE. No graphify; the prose-graph waiver holds.

## Signal/noise / consumer (the framing decision — pin before building)

- **`4DLab_UI_FieldMap.md` → FRAME.** Consumer is real and existing: the wired diagnosis screen
  **`apps/4DLabWired/app.py`** implements the field placement/visibility the map specifies, and each
  field's consumer chain resolves to a live lab schema (verified by `T-UI-SYNC-1`). `consumers:` ≥ 1,
  e.g. `apps/4DLabWired/app.py` (field-placement implementation) + `apps/4DLabWired/wired/composition.py`
  (the payload wiring the fields feed). `node_type:` a design type (e.g. `design` / `doc`); it routes
  to the docs tier.
- **`StreamliteUI.md` → FRAME only if a consumer can be named** — the DNA-driven rendering pattern it
  defines is read by `app.py` (§1.5 of the FieldMap cites it as the rendering source). If that holds on
  a grep, frame with consumer `apps/4DLabWired/app.py` (rendering pattern). If not, leave it **`plain:`**
  (signal/noise — do not fabricate a consumer).
- **No lab is ever a consumer of a UI note** — the UI is downstream of every lab. Consumers are the
  **app layer only**.

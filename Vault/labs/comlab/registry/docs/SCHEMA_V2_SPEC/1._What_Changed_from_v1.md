## 1. What Changed from v1

The v1 architecture (`COMLab/comlab/config/global_fault_registry.json`) gates every
rule on a single hard-coded `gas_lab_state` field. Only 11 of 32 GASLab chemistry
states appear across 53 rules. The two most common chemistry signatures in failing
traces — `TIMING_RETARDED` (64 curated cases) and `SAMPLE_INVALID` (17 cases) —
have zero matching rules, guaranteeing 100% prune for ~32% of the curated corpus
before evaluation begins (AUDIT-REG §1, CHEMISTRY_COVERAGE §1).

v2 decouples evidence from gating:

### v1: One chemistry gate key per rule
- **v2**: List of chemistry states, each weighted (Evidence Tier)

### v1: DTC `REQUIRE_MATCH` / `REQUIRE_DTC` prune
- **v2**: DTC presence is evidence, not a gate

### v1: OBD constraints as a block
- **v2**: Each PID constraint individually weighted

### v1: Single-winner scoring
- **v2**: Competition groups — multiple rules fire, highest score wins

### v1: No confidence bounds
- **v2**: Confidence ceilings enforce "no solo survivor" discipline

### v1: Rules in one monolithic JSON
- **v2**: One JSON file per fault family under `rules/`
